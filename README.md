# Royal Hearth — King's Dine

A production-ready Next.js 14 (App Router) rebuild of the 9 static "King's Dine" screens
generated by Stitch AI, using the **Royal Hearth** design system (`royal_hearth/DESIGN.md`).

## Stack

- **Framework:** Next.js 14 (App Router), TypeScript (strict mode)
- **Styling:** Tailwind CSS, design tokens ported 1:1 from `DESIGN.md`
- **Validation:** Zod (login, signup, contact, track-order forms)
- **State:** React Context + `useReducer` for the cart (no external state library needed at this size)

## What's implemented

| Route | Real interactivity |
|---|---|
| `/` | Hero, value props strip, popular items rail |
| `/menu` | Client-side category filter chips, add-to-cart, empty state per category |
| `/special-deals` | Promo code copy-to-clipboard |
| `/track-order` | Validated order-ID lookup (loading / success / not-found states), progress bead tracker |
| `/locations` | Live search-as-you-type filtering, simulated "use current location" |
| `/contact` | Zod-validated form, loading/success/error states |
| `/about` | Static brand + journey content |
| `/login` | Zod-validated auth form, password visibility toggle, simulated auth |
| `/signup` | Full validation (name, email, password strength, confirm match, terms checkbox) |

Shared across every page: sticky header with a **working mobile hamburger menu**
(not just a static icon), a bottom tab bar that highlights the active route, and a
cart badge that updates in real time as items are added from any page.

All forms currently simulate their network calls (`setTimeout`) with comments marking
exactly where to wire in real API endpoints — see `src/lib/validation.ts` for the
schemas, which are designed to be reused server-side for re-validation.

## Notes on trade-offs made during conversion

1. **Fonts via `<link>`, not `next/font/google`.** `next/font` self-hosts Google Fonts
   at build time, which is generally the better default (no runtime request, no CLS).
   It requires build-time network access to `fonts.googleapis.com`, though — some CI
   runners restrict egress to that host, which turns a font choice into a broken build.
   Plain `<link>` tags degrade gracefully to system fonts and keep the build hermetic.
   If your CI/deploy target has open egress (Vercel does), swapping back to `next/font`
   in `src/app/layout.tsx` is a quick, low-risk upgrade for slightly better performance.
2. **Images use the original Stitch/AIDA-generated photo URLs** from the source mockups,
   served through `next/image` with `remotePatterns` configured for `lh3.googleusercontent.com`
   in `next.config.mjs`. Swap in your own CDN-hosted photography when ready — no other
   code changes required, `next/image` will keep optimizing whatever you point it at.
3. **Menu has two categories (Sides, Beverages) with no items yet** — deliberately, since
   the source mockups only ever depicted 7 items across 4 categories. Selecting those
   chips shows a real empty state rather than fabricated placeholder items with made-up
   photos and prices.

## Deploying to Vercel (via GitHub)

1. **Verify locally**
   ```bash
   npm install
   npm run build
   ```
2. **Push to GitHub**
   ```bash
   git init
   git add .
   git commit -m "Initial commit: Royal Hearth Next.js app"
   git branch -M main
   git remote add origin <your-repo-url>
   git push -u origin main
   ```
3. **Import into Vercel**
   - New Project → import the GitHub repo
   - Framework preset: **Next.js** (auto-detected)
   - Build command: `npm run build`
   - Output directory: leave default (`.next` — Next.js preset handles this)
4. **Deploy**, then verify the live URL renders all 9 routes.
5. *(Optional)* attach a custom domain under Project → Settings → Domains.

No environment variables are required for the current build — everything runs
client-side against local mock data. When you wire up a real backend (auth, orders,
contact form delivery), add those secrets under Project → Settings → Environment Variables
rather than committing them.
